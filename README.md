# וורדי · Wordi

A Hebrew semantic word-guessing game inspired by [Semantle](https://semantle.ishefi.com/).
Guess the secret word; each guess gets a similarity score (cosine similarity × 100) from Hebrew
word embeddings. Words among the secret's 1000 nearest neighbours show their rank (`1000/1000` = closest).

- **Daily challenge**: one word for everyone, changes at midnight Israel time, one official attempt per player, public leaderboard.
- **Free play**: random words, unlimited games.
- Full RTL Hebrew UI, mobile-first, vanilla JS + Tailwind; FastAPI + SQLite backend.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the file layout, DB schema and design notes.

## Quick start (demo vectors, ~10 seconds)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt          # or requirements.txt to skip pytest/gensim
python scripts/make_demo_vectors.py          # SYNTHETIC vectors — scores are meaningless
uvicorn wordi.main:create_app --factory --reload
# open http://localhost:8000
```

## Real Hebrew vectors

```bash
python scripts/prepare_vectors.py
```

By default this streams fastText's Common Crawl Hebrew vectors
(`cc.he.300.vec.gz`, 1.2 GB compressed). The file is sorted by frequency, so the script reads
only the head of it — the 50K most frequent Hebrew words plus any secret words found a little
further down — and stops. Expect roughly **100–200 MB** of download and a few minutes.
It writes:

| file | content |
|---|---|
| `data/vectors/he.npz` | words + float16 L2-normalised vectors (~30 MB for 50K × 300) |
| `data/vectors/neighbors.npz` | top-1000 neighbours of every secret word (startup cache) |

Options: `--vocab-size 30000`, `--max-lines 200000`, or `--input FILE` for a local
`.vec`/`.vec.gz`/`.txt` (word2vec text, no gensim needed), fastText `.bin`, word2vec `.bin`
(`--word2vec-binary`), or a gensim `.kv`/`.model` (these need `pip install gensim`).

Tokens are kept only if they are Hebrew letters (with optional geresh/gershayim), at least two
letters long; niqqud is stripped. After editing `data/secret_words.json`, re-run
`python scripts/precompute_neighbors.py` (optional; the server computes missing neighbours on demand).
Secret words missing from the vocabulary are skipped with a warning at startup.

## Running

```bash
uvicorn wordi.main:create_app --factory --host 0.0.0.0 --port 8000
```

Environment variables (all optional):

| variable | default | |
|---|---|---|
| `WORDI_DB_URL` | `sqlite:///data/wordi.db` | SQLAlchemy URL |
| `WORDI_VECTORS` | `data/vectors/he.npz` | |
| `WORDI_NEIGHBORS` | `data/vectors/neighbors.npz` | |
| `WORDI_SECRET_WORDS` | `data/secret_words.json` | |
| `WORDI_EPOCH` | `2026-01-01` | date of puzzle #1 |
| `WORDI_DAILY_SALT` | `wordi-v1` | changing it reshuffles the daily order |
| `WORDI_TZ` | `Asia/Jerusalem` | |
| `WORDI_TRUST_PROXY` | `0` | `1` = rate-limit by `X-Forwarded-For` (only behind your own proxy) |
| `WORDI_RATE_LIMIT` | `1` | `0` disables rate limiting |

### Docker

```bash
python scripts/prepare_vectors.py            # on the host, once
docker build -t wordi .
docker run -p 8000:8000 -v "$PWD/data/vectors:/app/data/vectors:ro" -v wordi-db:/app/data/db wordi
```

### Rebuilding the CSS

`web/app.css` is committed, so Node is only needed if you change Tailwind classes:

```bash
cd tailwind && npm install && npm run build      # or: npm run watch
```

## Tests

```bash
pytest
```

Covers Hebrew normalisation and prefix stripping, similarity and rank logic, the neighbour cache,
daily-word selection (including the Israel-midnight boundary in winter and summer), game flows
(validation, duplicates, hints, give-up, secret never leaked), leaderboard ordering, submission
rules, name validation/profanity and rate limiting.

## API

| method | path | |
|---|---|---|
| GET | `/api/daily-info` | puzzle number, date, similarity of 1st/10th/1000th neighbour, time to reset |
| GET | `/api/yesterday` | yesterday's word and its 10 nearest words |
| POST | `/api/daily/session` | the player's (single) daily session, created on first call |
| POST | `/api/free/new` | new free-play session |
| GET | `/api/session/{id}` | session state (secret only once solved / given up) |
| POST | `/api/guess` | `{mode, session_id?, word}` → `{valid, word, similarity, rank, solved, …}` |
| GET | `/api/hint?session_id=` | reveals a word ranked between the best guess and the secret |
| POST | `/api/giveup` | `{session_id}` → `{secret}` |
| POST | `/api/leaderboard` | `{session_id, name}` — only for a solved, hint-free daily session |
| GET | `/api/leaderboard?scope=today\|yesterday\|alltime&sort=wins\|fastest` | |

Interactive docs at `/api/docs`. Requests identify the player with an anonymous UUID sent as
`X-Player-Id` (and the `wordi_pid` cookie), generated by the browser and kept in localStorage.

## Fair play

- Every guess is recorded server-side with a timestamp; the leaderboard takes guess count and
  time (first guess → solve) from those rows. The client only sends a session id and a name.
- One daily session per player id per day (unique index), one leaderboard entry per player per day.
- Hints mark the session; hinted or given-up runs cannot be submitted.
- Secrets are never sent before the game ends. Session ids are 128-bit random.
- Per-IP sliding-window rate limits (guesses, hints, new games, submissions).
- Names: 2–20 Hebrew/English letters, digits and spaces; small Hebrew + English profanity list;
  rendered with `textContent` only.

These are basic protections: a determined player can still mint new anonymous ids.
